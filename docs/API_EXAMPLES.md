# API examples

Start the server using the README. These commands use Bash syntax and require `TASK_API_KEY` in your shell. Do not paste a real key into documentation.

```bash
BASE_URL=http://127.0.0.1:8000
```

## Create

```bash
curl -i "$BASE_URL/tasks" \
  -H "Authorization: Bearer $TASK_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Review supplier invoice","owner":"Mariam","priority":"high","due_date":"2026-12-01"}'
```

Returns **201 Created**, a `Location: /tasks/1` header, and a task object:

```json
{
  "id": 1,
  "title": "Review supplier invoice",
  "description": null,
  "owner": "Mariam",
  "status": "todo",
  "priority": "high",
  "due_date": "2026-12-01",
  "created_at": "2026-10-22T16:00:00Z"
}
```

IDs and creation timestamps are generated by the service. The values above are illustrative.

## List with filtering and pagination

```bash
curl "$BASE_URL/tasks?status=todo&owner=Mariam&limit=10&offset=0" \
  -H "Authorization: Bearer $TASK_API_KEY"
```

Response shape:

```json
{"items": [], "total": 0, "limit": 10, "offset": 0}
```

`items` contains matching tasks; it is empty when there are no matches. `total` counts all matches before pagination. Supported statuses: `todo`, `in_progress`, `done`. Priorities: `low`, `medium`, `high`.

## Get, update and delete

Replace `1` with the ID returned by create.

```bash
curl "$BASE_URL/tasks/1" -H "Authorization: Bearer $TASK_API_KEY"

curl -X PATCH "$BASE_URL/tasks/1" \
  -H "Authorization: Bearer $TASK_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"status":"done","due_date":null}'

curl -i -X DELETE "$BASE_URL/tasks/1" \
  -H "Authorization: Bearer $TASK_API_KEY"
```

Get and update return **200**. Delete returns **204** with no body. `due_date`, `description` and `owner` can be cleared with null. Empty PATCH bodies are rejected.

## Errors

| Request | Status | Meaning |
| --- | ---: | --- |
| Missing or wrong bearer key | 401 | Missing or invalid API key |
| Valid request for an unknown positive ID | 404 | Task not found |
| Blank title, invalid status/date or invalid pagination | 422 | Field validation failed |
| Extra request fields such as `id` or `created_at` | 422 | Unknown fields are forbidden |

```bash
curl -i "$BASE_URL/tasks"
# 401 {"detail":"Missing or invalid API key"}

curl -i "$BASE_URL/tasks/999999" -H "Authorization: Bearer $TASK_API_KEY"
# 404 {"detail":"Task not found"}

curl -i "$BASE_URL/tasks?limit=0" -H "Authorization: Bearer $TASK_API_KEY"
# 422 with a structured validation error
```

## Swagger UI

Open `http://127.0.0.1:8000/docs`, click **Authorize**, paste only your key, then select **Try it out** on an endpoint. The UI adds the `Bearer` prefix. `/openapi.json` provides the machine-readable API contract. Docs are public in local demo mode; task data still requires authentication.
